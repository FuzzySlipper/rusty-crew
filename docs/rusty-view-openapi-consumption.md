# Rusty View OpenAPI Consumption

Status: active contract and certification guidance for task 5409

Rusty View consumes Rusty Crew wire types without surrendering transport
behavior to a generated client. `openapi-typescript` generates type-only output;
Rusty View continues to own explicit `fetch`, SSE replay, reconnect, auth, and
error-envelope handling.

## Inputs And Ownership

Use this as the Rusty View generator input:

```text
docs/rusty-view-chat-api-v0.openapi.json
```

That chat document references generated command and capability discovery
operations from:

```text
docs/rusty-crew-api-capabilities.openapi.json
```

The generated capability document is owned by
`ts/packages/brain-island/src/api-command-registry.ts` and regenerated by
`generate-api-capability-artifact.ts`. Do not copy its command descriptors,
capability descriptors, operation ids, or enums into a second frontend schema.

External-agent runtime operations use the versioned generated contract:

```text
docs/external-runtime-api-v0.openapi.json
```

Use that artifact for fleet, binding, thread, event/SSE, control, interaction,
delivery, and correlated-round types. Its Crew-owned thread projections and
Rust-derived coordination schemas are the browser wire authority; Codex
app-server protocol files are not a frontend contract.

The capability document lists every public operation, but only operations with
`x-rusty-crew-contract-detail: wire` promise detailed response types. Operations
marked `capability` are discovery metadata; their detailed body contracts remain
in the owning domain OpenAPI or schema.

## Generation

Rusty View's type-only generation remains:

```bash
pnpm exec openapi-typescript \
  /home/dev/rusty-crew/docs/rusty-view-chat-api-v0.openapi.json \
  -o libs/protocol/src/generated/openapi.ts
```

The generated graph exposes these stable operation ids:

- `listChatCommands`
- `autocompleteChatCommandArgument`
- `listApiCapabilities`

It also exposes `ChatCommandRegistry`, `ChatCommandDescriptor`,
`ChatCommandAutocompleteResult`, `ApiCapabilityRegistry`, and
`ApiCapabilityDescriptor` component schemas. Rusty View may publish ergonomic
type aliases from its protocol package, but transport code should remain
hand-written and typed against those aliases.

## Backend Drift Checks

Run these before frontend regeneration:

```bash
npm run codegen:api-capabilities
npm run check:api-capabilities
npm run smoke:api-command-registry
npm run smoke:external-runtime-api-contract
```

The check regenerates both committed capability artifacts and compares them
exactly. The smoke proves generated OpenAPI method/path pairs match the public
capability registry and that the chat document references generated command
operations and schemas.

## Browser Certification

Certification targets the debug service at `http://127.0.0.1:9348` and must run
in a real browser context through Rusty View. The scenario is deliberately
read-only:

1. Load Rusty View from the debug service and wait for the application shell.
2. From the same browser origin, fetch `/v1/admin/capabilities` and
   `/v1/chat/commands` through the application's configured transport/auth
   context.
3. Assert both responses are successful Rusty Crew envelopes.
4. Compare capability `(method, path_template, id)` tuples with
   `fixtures/api-capabilities/api-command-capabilities.json`.
5. Compare command names and descriptors with the same generated fixture.
6. Assert the UI's command discovery transport can list the returned commands;
   no generated HTTP client may be introduced to make the smoke pass.
7. Save the Playwright trace, screenshot, and response summary as task evidence.

Use the Playwright broker procedure in
`den-services/playwright-broker-agent-usage`. A mismatch in envelope shape,
auth semantics, route behavior, or frontend transport behavior is not a
mechanical finalizer fix; hand it back for contract or product review.
